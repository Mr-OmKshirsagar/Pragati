# PRAGATI — PROJECT CONTEXT

## 1. Project Identity

**Product Name:** PRAGATI

**Product Title:** Smart Student Internship & Career Management Platform

**Tagline:** From Student Progress to Career Readiness

**Problem Statement:** ED-06

> Develop a Smart Internship Management and Monitoring System that enables institutions to digitally monitor and manage the complete internship lifecycle of students through a single, secure and scalable platform.

---

## 2. Product Purpose

PRAGATI is an institution-focused platform designed to manage and monitor the student journey from skill development through internship and placement readiness.

The long-term vision is a four-year student career lifecycle.

However, the hackathon implementation must focus on a deep, working vertical slice rather than attempting to build a complete ERP.

---

## 3. Core Problem

Current institutional workflows often have:

* Academic data in ERP systems
* Certificates in email/WhatsApp/drive folders
* Internship documents stored separately
* Manual internship verification
* Placement eligibility calculated using spreadsheets
* Faculty interventions tracked informally
* Skill gaps discovered too late
* No unified student career record

PRAGATI aims to create continuity between these processes.

---

## 4. Core Principle

PRAGATI is not simply a record-keeping system.

It is an:

**Evidence + Monitoring + Intervention + Verification + Eligibility platform.**

---

## 5. Primary Workflow

Student data
→ Academic performance
→ Skill assessments
→ Skill-gap detection
→ Faculty intervention
→ Progress measurement
→ Internship
→ Evidence collection
→ Verification
→ Placement criteria
→ Eligibility evaluation
→ Recruitment
→ Career Passport

---

## 6. Primary Users

### Student

Manages permitted profile information, achievements, assessments, internship evidence and applications.

### Faculty / Teacher Guardian

Monitors assigned students, manages interventions and verifies internship evidence.

### HOD

Monitors department-level performance and intervention trends.

### T&P Coordinator

Manages recruitment drives and eligibility criteria.

### Admin

Manages institution configuration, users, departments, skills and system settings.

---

## 7. Hackathon Objective

The prototype must demonstrate that:

1. Student data can be centralized.
2. Skill gaps can be detected transparently.
3. Faculty can intervene.
4. Internship evidence can be collected.
5. Evidence integrity can be checked.
6. Internship completion can be reviewed.
7. T&P can create configurable eligibility criteria.
8. Students can be evaluated transparently.
9. Recruitment opportunities can be published.
10. A student can view an evidence-backed career profile.

---

## 8. Non-Goals

The hackathon will NOT attempt to build:

* A complete college ERP
* A complete LMS
* A complete HR/recruitment platform
* A production-grade mobile application
* A nationwide student database
* Full blockchain infrastructure
* Autonomous AI decision-making
* 100% fraud-proof internship verification

---

## 9. Technical Philosophy

Prioritize:

1. Correctness
2. Security
3. Reliability
4. Explainability
5. Testability
6. User experience
7. Performance
8. Advanced features

Avoid unnecessary complexity.

---

## 10. Truthfulness Principle

Never claim that a feature is implemented unless it actually works.

Never claim:

* SHA-256 proves authenticity
* AI determines employability
* internship verification is fraud-proof
* synthetic data is real institutional data

Be technically honest.
